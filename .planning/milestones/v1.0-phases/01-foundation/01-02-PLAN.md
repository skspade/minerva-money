<feature>
  <name>PRAGMA user_version Migration Runner + Initial Schema</name>
  <files>
    packages/server/src/db/connection.ts,
    packages/server/src/db/migrate.ts,
    packages/server/src/db/migrate.test.ts,
    packages/server/migrations/001-initial-schema.sql
  </files>
  <behavior>
    - migrate() on empty database applies all migrations and sets user_version
    - migrate() on up-to-date database is a no-op (idempotent)
    - migrate() on partially-migrated database applies only pending migrations
    - All money columns (amount, balance, etc.) are INTEGER type
    - transactions table has UNIQUE constraint on transactionId (primary dedup)
    - transactions table has UNIQUE index on hash of account+date+amount+merchant (fallback dedup)
    - WAL journal mode is enabled after connection
    - Foreign keys are enforced
  </behavior>
  <implementation>
    1. Create `packages/server/src/db/connection.ts`:
       - `createDatabase(dbPath?)` function
       - Opens better-sqlite3 database at given path (default: `~/minerva-money/data/minerva.db`)
       - Sets `PRAGMA journal_mode = WAL`
       - Sets `PRAGMA foreign_keys = ON`
       - Calls `migrate(db, migrationsDir)` on creation
       - Returns the database instance

    2. Create `packages/server/src/db/migrate.ts`:
       - `migrate(db, migrationsDir)` function
       - Reads `PRAGMA user_version` as current version
       - Lists `.sql` files in migrationsDir, sorted by zero-padded numeric prefix
       - For each file with version > current: read SQL, execute in transaction, set `PRAGMA user_version`
       - Returns count of migrations applied

    3. Create `packages/server/migrations/001-initial-schema.sql` with ALL tables:
       - `accounts`: id (TEXT PK), name, institution, type, subtype, balance (INTEGER), currency, last_synced, simplefin_id (TEXT UNIQUE), created_at, updated_at
       - `transactions`: id (TEXT PK -- transactionId from SimpleFIN), account_id (FK), date, amount (INTEGER), pending (BOOLEAN), payee, memo, category_id (FK nullable), dedup_hash (TEXT), created_at, updated_at. UNIQUE index on dedup_hash.
       - `categories`: id (INTEGER PK AUTOINCREMENT), group_id (FK), name, sort_order, created_at
       - `category_groups`: id (INTEGER PK AUTOINCREMENT), name, sort_order, created_at
       - `budget_allocations`: id (INTEGER PK AUTOINCREMENT), category_id (FK), period (TEXT YYYY-MM), amount (INTEGER), is_default (BOOLEAN), created_at, updated_at. UNIQUE on (category_id, period).
       - `categorization_rules`: id (INTEGER PK AUTOINCREMENT), name, merchant_pattern, amount_min (INTEGER nullable), amount_max (INTEGER nullable), memo_pattern, category_id (FK), specificity_score (INTEGER), created_at, updated_at
       - `transfer_links`: id (INTEGER PK AUTOINCREMENT), transaction_a_id (FK), transaction_b_id (FK), confirmed (BOOLEAN), created_at. UNIQUE on (transaction_a_id, transaction_b_id).
       - `balance_snapshots`: id (INTEGER PK AUTOINCREMENT), account_id (FK), date (TEXT), balance (INTEGER), created_at. UNIQUE on (account_id, date).
       - `sync_log`: id (INTEGER PK AUTOINCREMENT), started_at, completed_at, status (TEXT), error_message, accounts_synced (INTEGER), transactions_added (INTEGER)

       All money values (amount, balance, amount_min, amount_max) are INTEGER.
       All foreign keys reference parent tables.
       Include relevant indexes for query performance.
  </implementation>
</feature>

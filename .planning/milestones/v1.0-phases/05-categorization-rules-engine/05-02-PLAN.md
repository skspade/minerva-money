<feature>
  <name>Retroactive Preview/Apply and tRPC Router</name>
  <files>
    packages/server/src/rules/rules-service.ts,

  <behavior>
    Preview:
    - previewRule(db, ruleId) returns list of transactions that would be recategorized
    - Each preview item includes: transactionId, date, payee, amount, currentCategoryName (or null), proposedCategoryName
    - Only includes transactions where category_id IS NULL and no splits (uncategorized, non-split)
    - Also includes transactions categorized by a DIFFERENT rule (rule_id IS NOT NULL AND rule_id != this rule) since the more-specific rule should win
    - Actually, simplify: preview shows transactions where the rule matches AND (category_id IS NULL OR (rule_id IS NOT NULL meaning a rule set it))
    - Transactions manually categorized (category_id IS NOT NULL AND rule_id IS NULL) are excluded

    Apply:
    - applyRule(db, ruleId) retroactively applies the rule to all matching uncategorized transactions
    - Runs in a single database transaction
    - Sets category_id to the rule's category_id and rule_id to the rule's id
    - Only applies to transactions matching the preview criteria (same filter)
    - Returns count of updated transactions

    tRPC Router:
    - rules.list: returns all rules with category name
    - rules.create: input { name, merchantPattern?, matchType?, amountMin?, amountMax?, memoPattern?, categoryId }, returns created rule
    - rules.update: input { id, name?, merchantPattern?, matchType?, amountMin?, amountMax?, memoPattern?, categoryId? }
    - rules.delete: input { id }
    - rules.preview: input { id }, returns preview items
    - rules.apply: input { id }, returns { updatedCount }

    Extended transactions.list:
    - Add rule_id and rule_name to the query via LEFT JOIN on categorization_rules
    - Return ruleName in the response alongside existing fields
  </behavior>
  <implementation>
    1. Add previewRule and applyRule to rules-service.ts with tests

    2. Create rulesRouter in trpc-router.ts with all 6 procedures using Zod validation

    4. Extend transactions.list query:
       - LEFT JOIN categorization_rules cr ON t.rule_id = cr.id
       - Add cr.name AS rule_name to SELECT
       - Add ruleId and ruleName to response mapping
  </implementation>
</feature>

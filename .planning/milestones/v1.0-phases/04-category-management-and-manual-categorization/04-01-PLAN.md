  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))

  id INTEGER PRIMARY KEY AUTOINCREMENT,
  group_id INTEGER NOT NULL REFERENCES category_groups(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

  id TEXT PRIMARY KEY,

  pending INTEGER NOT NULL DEFAULT 0,
  payee TEXT,
  memo TEXT,
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  dedup_hash TEXT,
  ...
);

<task type="auto" tdd="true">
  <name>Task 1: Create migration and category service with tests</name>
  <files>packages/server/migrations/002-transaction-splits.sql, packages/server/src/categories/category-service.ts, packages/server/src/categories/category-service.test.ts</files>
  <behavior>
    - listGroupsWithCategories: returns all groups with nested categories sorted by sort_order
    - createGroup: inserts a group with name, returns the new group with id
    - renameGroup: updates group name by id
    - reorderGroups: accepts ordered array of group ids, sets sort_order sequentially (0, 1, 2...)
    - deleteGroup: deletes group by id (cascades to categories)
    - createCategory: inserts category with groupId and name, returns new category with id
    - renameCategory: updates category name by id
    - reorderCategories: accepts groupId and ordered array of category ids, sets sort_order sequentially
    - deleteCategory: deletes category by id (transactions.category_id becomes NULL via ON DELETE SET NULL)
    - updateTransactionCategory: sets category_id on a transaction, also deletes any existing splits for that transaction
    - createSplits: given transactionId and array of {categoryId, amount}, validates amounts sum to transaction total (absolute value), inserts splits, sets transaction category_id to NULL
    - deleteSplits: deletes all splits for a transaction
    - createManualTransaction: inserts transaction with crypto.randomUUID() as id, dedup_hash NULL, pending 0
    - Edge case: createSplits rejects when sum of split amounts does not equal transaction amount
    - Edge case: createSplits rejects when splits array is empty
  </behavior>
  <action>

       ```sql
       CREATE TABLE transaction_splits (

         category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
         amount INTEGER NOT NULL,
         created_at TEXT NOT NULL DEFAULT (datetime('now'))
       );
       CREATE INDEX idx_transaction_splits_transaction_id ON transaction_splits(transaction_id);
       ```

    2. Create `packages/server/src/categories/category-service.ts` with all service functions. Each function takes `db: Database.Database` as first argument. Use `db.transaction()` for reorder and split operations. Use `crypto.randomUUID()` for manual transaction IDs.

       - Split creation with valid amounts (sum matches transaction total)
       - Split creation rejection with invalid amounts (sum mismatch)
       - Split creation rejection with empty splits array
       - Manual transaction creation with UUID id
       - Cascade behavior: deleting a group removes its categories, deleting a category nullifies transaction.category_id

    - `groups.rename` — mutation, input: `{ id: number, name: string }`, calls renameGroup
    - `groups.reorder` — mutation, input: `{ ids: number[] }`, calls reorderGroups
    - `groups.delete` — mutation, input: `{ id: number }`, calls deleteGroup
    - `create` — mutation, input: `{ groupId: number, name: string }`, calls createCategory
    - `rename` — mutation, input: `{ id: number, name: string }`, calls renameCategory
    - `reorder` — mutation, input: `{ groupId: number, ids: number[] }`, calls reorderCategories
    - `delete` — mutation, input: `{ id: number }`, calls deleteCategory

    Extend the existing `transactionsRouter` with:
    - `updateCategory` — mutation, input: `{ transactionId: string, categoryId: number | null }`, calls updateTransactionCategory
    - `createSplits` — mutation, input: `{ transactionId: string, splits: Array<{ categoryId: number, amount: number }> }`, calls createSplits
    - `deleteSplits` — mutation, input: `{ transactionId: string }`, calls deleteSplits
    - `create` — mutation, input: `{ accountId: string, date: string, amount: number, payee: string, memo?: string, categoryId?: number }`, calls createManualTransaction

    Update the `transactions.list` query to LEFT JOIN categories and category_groups for display names, and include a split_count subquery:
    ```sql
    SELECT t.id, t.date, t.payee, t.memo, t.amount, t.account_id,
      a.name AS account_name, t.category_id,
      c.name AS category_name, cg.name AS group_name,
      (SELECT COUNT(*) FROM transaction_splits ts WHERE ts.transaction_id = t.id) AS split_count
    FROM transactions t
    JOIN accounts a ON t.account_id = a.id
    LEFT JOIN categories c ON t.category_id = c.id
    LEFT JOIN category_groups cg ON c.group_id = cg.id
    ORDER BY t.date DESC, t.created_at DESC
    ```

    Return `categoryName`, `groupName`, and `splitCount` in the mapped response.

    Add `categories: categoriesRouter` to `appRouter`.

    Use Zod v4 for all input schemas (already a dependency).

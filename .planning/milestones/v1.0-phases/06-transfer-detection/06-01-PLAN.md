<feature>
  <name>Transfer Detection Service</name>
  <files>packages/server/src/transfers/transfer-service.ts, packages/server/src/transfers/transfer-service.test.ts</files>
  <behavior>
    Transfer candidate detection:
    - Given transactions on different accounts where amount_a = -amount_b within 3-day window, detectTransferCandidates returns them as candidates
    - Given two transactions on the SAME account, they are NOT matched as candidates
    - Given transactions with non-offsetting amounts, they are NOT matched
    - Given transactions outside the 3-day date window, they are NOT matched
    - Given pending transactions (pending = 1), they are excluded from detection
    - Given a transaction already in transfer_links (any status), it is NOT re-matched
    - Canonical ordering: transaction_a_id has earlier date (or lower ID if same date)
    - Inserting a duplicate pair (same two transactions) does not error (UNIQUE constraint handled)

    Confirm/dismiss/unlink:
    - confirmTransfer(db, linkId) sets confirmed = 1
    - dismissTransfer(db, linkId) sets confirmed = -1
    - unlinkTransfer(db, linkId) deletes the row from transfer_links
    - confirmTransfer on non-existent linkId throws an error
    - dismissTransfer on non-existent linkId throws an error

    Manual linking:
    - manuallyLinkTransfer(db, txnAId, txnBId) inserts a row with confirmed = 1
    - Manual link enforces canonical ordering (earlier date first)
    - Manual link on same-account transactions throws an error

    List queries:
    - listTransferCandidates returns all confirmed=0 rows with both transactions' details (date, payee, amount, account_name)
    - listConfirmedTransfers returns all confirmed=1 rows with both transactions' details
  </behavior>
  <implementation>
    1. Create migration 004-transfer-indexes.sql with indexes on transaction_a_id, transaction_b_id, and confirmed columns.

    2. Create packages/server/src/transfers/transfer-service.ts with:
       - DEFAULT_DATE_WINDOW_DAYS = 3
       - detectTransferCandidates(db, transactionIds, dateWindowDays = DEFAULT_DATE_WINDOW_DAYS): Queries transactions matching the given IDs, then for each, finds offsetting-amount transactions on different accounts within the date window that are not pending and not already in transfer_links. Uses canonical ordering for insertion. Returns count of candidates found.
       - confirmTransfer(db, linkId): UPDATE transfer_links SET confirmed = 1 WHERE id = ? — throws if no rows affected.
       - dismissTransfer(db, linkId): UPDATE transfer_links SET confirmed = -1 WHERE id = ? — throws if no rows affected.
       - unlinkTransfer(db, linkId): DELETE FROM transfer_links WHERE id = ? — throws if no rows affected.
       - manuallyLinkTransfer(db, txnAId, txnBId): Validates different accounts, enforces canonical order, inserts with confirmed = 1. Returns the created link.
       - listTransferCandidates(db): SELECT with JOINs on transactions and accounts for both sides, WHERE confirmed = 0.
       - listConfirmedTransfers(db): Same JOIN pattern, WHERE confirmed = 1.

    3. Add transfersRouter to trpc-router.ts:

  <name>chatStream async generator</name>
  <files>packages/server/src/agent/agent-service.ts, packages/server/src/agent/agent-service.test.ts</files>
  <behavior>
    ## Core Streaming (SRVR-03)
    - Given an SDK that emits an init system message, chatStream yields an SSESessionEvent with the session_id
    - Given an SDK that emits stream_event with content_block_delta/text_delta, chatStream yields SSETextDeltaEvent with the delta text
    - Given an SDK that emits a result/success message, chatStream yields SSEDoneEvent with full accumulated text
    - Given an SDK that emits a result/error message, chatStream yields SSEErrorEvent with error description and partial text
    - chatStream ignores irrelevant SDK message types (status, compact_boundary, etc.)

    ## Tool Events (SRVR-04)
    - Given an SDK stream_event with content_block_start where content_block.type is 'tool_use', chatStream yields SSEToolStartEvent with the tool name
    - Given an SDKUserMessage with tool_use_result after a tool was active, chatStream yields SSEToolEndEvent for active tools
    - Duplicate tool-start events are not emitted for the same tool name (tracked via Set)

    ## Abort Handling (SRVR-05)
    - Given an AbortSignal that fires during iteration, chatStream breaks out of the loop without yielding further events
    - The abort listener calls query.close() to clean up the SDK subprocess
    - The abort listener is removed in the finally block to prevent memory leaks

    ## Idle Timeout (SRVR-06)
    - Given no SDK messages arrive within TIMEOUT_MS[model] milliseconds, chatStream yields SSEErrorEvent with timeout message and partial text, then returns
    - The idle timer resets after each received SDK message
    - The idle timer is cleared on normal completion

    ## Text Accumulation
    - All text deltas are accumulated into fullText
    - SSEDoneEvent.text contains the complete accumulated text
    - SSEErrorEvent.partialText contains whatever text was accumulated before the error

    ## Error Handling
    - Unexpected exceptions are caught and yield SSEErrorEvent with the error message
    - The generator never re-throws -- it always terminates gracefully
  </behavior>
  <implementation>
    Add `chatStream()` to agent-service.ts as an exported async generator function. It should:

    1. Accept same params as `chat()` plus `signal: AbortSignal` — signature: `(db, ctx, message, signal, sessionId?, model?)`
    2. Set up MCP server and system prompt identically to `chat()` using `createMcpServer(db, ctx)` and `getSystemPrompt()`
    3. Build options object matching `chat()` but adding `includePartialMessages: true`
    4. Call `query({ prompt: message, options })` to get the `Query` async generator
    5. Register abort listener: `signal.addEventListener('abort', () => queryStream.close())`
    6. Set up idle timeout using `setTimeout` with `TIMEOUT_MS[model]` — reset on each message, call `queryStream.close()` on fire, set a flag to distinguish timeout from abort
    7. Iterate with `for await (const msg of queryStream)`:
       - Check `signal.aborted` at top of loop — break if true
       - `msg.type === 'system' && msg.subtype === 'init'` → yield `{ type: 'session', sessionId: msg.session_id }`
       - `msg.type === 'stream_event'`:
         - `event.type === 'content_block_delta' && event.delta.type === 'text_delta'` → accumulate text, yield `{ type: 'text-delta', text: event.delta.text }`
         - `event.type === 'content_block_start' && event.content_block.type === 'tool_use'` → add to activeTools Set, yield `{ type: 'tool-start', tool: event.content_block.name }`
       - `msg.type === 'user' && msg.tool_use_result !== undefined` → for each tool in activeTools, yield `{ type: 'tool-end', tool }`, then clear set
       - `msg.type === 'result' && msg.subtype === 'success'` → yield `{ type: 'done', text: fullText || msg.result }`
       - `msg.type === 'result' && msg.subtype starts with 'error'` → yield `{ type: 'error', message: msg.errors?.join('; ') || 'Agent error', partialText: fullText || undefined }`
    8. After loop: if `idleTimedOut`, yield `{ type: 'error', message: 'Agent query idle timeout...', partialText: fullText || undefined }`
    9. Wrap everything in try/catch — on caught error, yield SSEErrorEvent
    10. In finally block: clear idle timer, remove abort listener

    For tests: Mock `query()` from the SDK to return a fake async generator that yields controlled SDKMessage sequences. Test each behavior independently. Use `vi.mock` to mock `@anthropic-ai/claude-agent-sdk`. Also mock `createMcpServer` and `getSystemPrompt` since they require database access.

    Use type assertions (as any / as unknown) for SDK message mocks since the full SDK types have many required fields -- only include the fields chatStream actually reads.
  </implementation>

    - When state.sessionId is set (resume), chatStream passes options.resume to SDK query
    - When SDK query with resume throws an error, chatStream catches it, starts a new session without resume, and continues normally
    - On fallback, if state.conversationId is set, chatStream loads last 20 messages via getConversation and prepends them to the user message
    - buildFallbackPrompt(messages, userMessage) formats: "[Previous conversation context - last N messages]\nUser: ...\nAssistant: ...\n[End of context]\n\n{userMessage}"
    - buildFallbackPrompt limits to last 20 messages and truncates individual messages at 500 chars
    - On fallback, state.sessionId is cleared so the handler knows a new session started
    - chat() function gains optional conversationId parameter and returns it in ChatResult
  </behavior>
  <action>
    1. Add `buildFallbackPrompt` helper function (not exported, internal):
       ```typescript
       function buildFallbackPrompt(
         messages: Array<{ role: string; content: string }>,
         userMessage: string,
       ): string {
         const recent = messages.slice(-20);
         const contextLines = recent.map(m => {
           const truncated = m.content.length > 500 ? m.content.slice(0, 500) + '...' : m.content;
           return `${m.role === 'user' ? 'User' : 'Assistant'}: ${truncated}`;
         });
         return `[Previous conversation context - last ${recent.length} messages]\n${contextLines.join('\n')}\n[End of context]\n\n${userMessage}`;
       }
       ```
    2. In `chatStream`, wrap the SDK `query()` call in a try-catch for the resume case:
       - If `state.sessionId` is set, try `query({ prompt: message, options: { ...options, resume: state.sessionId } })`
       - On catch: log warning `console.warn('SDK resume failed, falling back to new session:', error.message)`
       - Load conversation messages if `state.conversationId` is set: `const conv = getConversation(db, state.conversationId)`
       - Build fallback prompt: `const fallbackMessage = conv?.messages?.length ? buildFallbackPrompt(conv.messages, message) : message`
       - Clear `state.sessionId = ''` to indicate new session
       - Start new query without resume: `query({ prompt: fallbackMessage, options })`
    3. Update `ChatResult` to include `conversationId?: string`.
    4. Update `chat()` function signature to accept optional `conversationId` parameter. Pass it through to the return value. Note: `chat()` still uses the existing `collectResponse` approach, not `StreamState`, because it's the non-streaming path. The `conversationId` pass-through enables the handler/router to track it.
    5. Add tests:
       - Test: resume succeeds, state.sessionId updated with new value from SDK
       - Test: resume fails, falls back to new session, state.sessionId cleared
       - Test: buildFallbackPrompt formats messages correctly
       - Test: buildFallbackPrompt limits to 20 messages
       - Test: buildFallbackPrompt truncates long messages at 500 chars
  </action>

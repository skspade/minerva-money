  <behavior>
    - chatStreamSchema accepts optional conversationId (z.string().uuid().optional())
    - chatStreamSchema no longer includes sessionId (removed -- server manages session IDs internally via conversationId)
    - When no conversationId: creates new conversation via createConversation, uses model from request (defaulting to DEFAULT_MODEL_ID)
    - When conversationId provided: loads conversation via getConversation; if not found, returns 400 JSON error BEFORE SSE headers
    - User message persisted via appendMessage BEFORE starting the stream
    - Conversation event { type: 'conversation', conversationId } written as first SSE event after headers
    - StreamState initialized with sessionId from loaded conversation's sdk_session_id (or empty string for new)
    - StreamState.conversationId set for fallback context loading
    - After generator loop: if state.sessionId differs from initial, updateSdkSessionId is called
    - After generator loop: if stream completed with a done event, assistant message persisted with state.fullText and state.toolCalls (try-catch on JSON.stringify of toolCalls, store null on failure)
    - Done event from generator is intercepted: persist assistant message FIRST, then write done event to response
    - On error/abort: assistant message is NOT persisted
  </behavior>

    3. In the handler function, after validation and model check, BEFORE setting SSE headers:
       ```typescript
       // Create or load conversation
       let conversationId: string;
       let sdkSessionId = '';

       if (parseResult.data.conversationId) {
         const existing = getConversation(db, parseResult.data.conversationId);
         if (!existing) {
           res.status(400).json({ error: `Conversation not found: ${parseResult.data.conversationId}` });
           return;
         }
         conversationId = existing.id;
         sdkSessionId = existing.sdk_session_id || '';
       } else {
         const validModel = (model as string) || DEFAULT_MODEL_ID;
         const created = createConversation(db, { model: validModel, firstMessage: message });
         conversationId = created.id;
       }

       // Persist user message before stream
       appendMessage(db, { conversationId, role: 'user', content: message });
       ```

    4. After setting SSE headers, BEFORE the stream loop:
       ```typescript
       // Emit conversation event first
       res.write(`data: ${JSON.stringify({ type: 'conversation', conversationId })}\n\n`);
       ```

    5. Initialize StreamState:
       ```typescript

         sessionId: sdkSessionId,
         fullText: '',
         toolCalls: [],

       };
       ```

    6. Call `chatStream(db, ctx, message, abortController.signal, state, model as ModelId | undefined)`.

    7. Change the stream loop to intercept `done` events:
       ```typescript
       let streamCompleted = false;
       for await (const event of stream) {
         if (event.type === 'done') {
           streamCompleted = true;
           // Persist assistant message BEFORE emitting done
           try {
             let toolCallsForStorage: unknown = null;
             if (state.toolCalls.length > 0) {
               try { toolCallsForStorage = state.toolCalls; } catch { /* store null */ }
             }
             appendMessage(db, {
               conversationId,
               role: 'assistant',
               content: state.fullText,
               toolCalls: toolCallsForStorage,
             });
           } catch (err) {
             console.warn('Failed to persist assistant message:', err);
           }
           // Update SDK session ID if changed
           if (state.sessionId && state.sessionId !== sdkSessionId) {
             updateSdkSessionId(db, conversationId, state.sessionId);
           }
           res.write(`data: ${JSON.stringify(event)}\n\n`);
           continue;
         }
         res.write(`data: ${JSON.stringify(event)}\n\n`);
       }
       ```
       Note: On error events, we do NOT persist the assistant message -- the conversation stays at its last successful state.

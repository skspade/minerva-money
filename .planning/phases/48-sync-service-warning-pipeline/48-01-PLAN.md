  <name>Sync Warning Pipeline</name>
  <files>packages/server/src/sync/sync-service.ts, packages/server/src/sync/sync-service.test.ts</files>
  <behavior>
    SYNC-01: Per-account warning persistence
    - When SimpleFIN returns errors with account_id, a row is UPSERTED into sync_warnings with the account_id, account_name (from accounts array, fallback to account_id), error_code, and message
    - When a per-account processing error occurs (caught in the inner try/catch), a warning is written with error_code='sync_error'
    - Repeated errors for the same account increment occurrence_count and update last_seen

    SYNC-02: Partial status logic
    - sync_log status = 'partial' when: API succeeded, accountsSynced > 0, AND at least one warning was written
    - sync_log status = 'success' when: API succeeded, zero warnings written
    - sync_log status = 'error' when: fetchAccounts() throws (existing behavior unchanged)

    SYNC-03: Warning auto-clear
    - After processing, DELETE sync_warnings rows for accounts that: (a) appeared in the SimpleFIN response AND (b) had no errors in this run
    - Accounts NOT in the SimpleFIN response retain their existing warnings

    SYNC-04: Connection-level error mapping
    - Errors with conn_id but no account_id are expanded to all accounts with matching conn_id in data.accounts
    - If conn_id matches zero accounts in response, write single warning with account_id=conn_id and account_name=conn_id

    Stale cleanup:
    - Before inserting new 'running' sync_log entry, UPDATE any existing 'running' entries to 'error' with error_message='Stale: superseded by new sync run' and completed_at=datetime('now')
  </behavior>
  <implementation>
    Modify runSync in packages/server/src/sync/sync-service.ts:

    1. Add a writeWarning helper function that does the UPSERT:
       INSERT INTO sync_warnings (sync_log_id, account_id, account_name, error_code, message)
       VALUES (?, ?, ?, ?, ?)
       ON CONFLICT(account_id) DO UPDATE SET
         sync_log_id = excluded.sync_log_id,
         error_code = excluded.error_code,
         message = excluded.message,
         last_seen = datetime('now'),
         occurrence_count = occurrence_count + 1

    2. Before the sync_log INSERT, add stale cleanup:
       UPDATE sync_log SET status = 'error', completed_at = datetime('now'), error_message = 'Stale: superseded by new sync run' WHERE status = 'running'

    3. Enhance the error iteration loop (lines 38-42):
       - Build a Map of conn_id -> SimpleFINAccount[] from data.accounts
       - Track errorAccountIds as a Set<string>
       - For each error: if account_id exists, resolve account_name from accounts array (fallback to account_id), call writeWarning, add to errorAccountIds
       - If conn_id but no account_id: look up accounts by conn_id, write warning for each (or single fallback if no accounts found), add all to errorAccountIds

    4. Enhance the per-account catch block (lines 57-60):
       - Call writeWarning with error_code='sync_error', add rawAccount.id to errorAccountIds

    5. After the account processing loop, add auto-clear:
       - Collect responseAccountIds from data.accounts
       - Filter to accounts NOT in errorAccountIds
       - DELETE FROM sync_warnings WHERE account_id IN (accountsToClear)

    6. Replace the hardcoded 'success' status update (line 64-66):
       - If errorAccountIds.size > 0 AND result.accountsSynced > 0: status = 'partial'
       - If errorAccountIds.size > 0 AND result.accountsSynced === 0: status = 'error' (all failed)
       - Else: status = 'success'

    Test approach: Create custom SimpleFINClient objects that return specific error scenarios. Use the existing test patterns (createDatabase, tmpDir, skipBackup). Query sync_warnings table directly to verify warning rows.

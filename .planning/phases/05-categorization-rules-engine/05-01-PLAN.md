  <behavior>
    Specificity scoring:
    - merchant exact match = 3 points
    - merchant contains match = 2 points
    - amount range with both bounds = 2 points
    - amount range with one bound = 1 point
    - memo pattern = 1 point
    - No conditions = error (at least one required)

    Rule matching (AND logic, all non-null conditions must match):
    - Merchant exact: case-insensitive exact match against payee
    - Merchant contains: case-insensitive substring match against payee
    - Amount min/max: compare against ABS(transaction.amount)
    - Memo: case-insensitive substring match against memo
    - Null conditions are skipped (not checked)

    Conflict resolution:
    - evaluateRules returns the single winning rule for a transaction
    - Rules sorted by specificity_score DESC, id DESC
    - First matching rule wins (most specific, ties to newer)
    - Returns null if no rules match

    CRUD:
    - createRule: validates at least one condition, computes specificity, inserts, returns rule with id
    - updateRule: validates, recomputes specificity, updates
    - deleteRule: deletes by id
    - listRules: returns all rules with category name, ordered by specificity_score DESC, id DESC

    Auto-categorization:
    - categorizeNewTransactions(db, transactionIds): evaluates rules on given transactions
    - Only processes transactions where category_id IS NULL and no splits exist
    - Sets category_id and rule_id on matching transactions
    - Skips transactions already manually categorized

    Sync integration:
    - After syncAccount inserts new transactions, collect new transaction IDs
    - Call categorizeNewTransactions with those IDs
  </behavior>
  <implementation>
    1. Create migration 003-rules-engine.sql:
       - ALTER TABLE categorization_rules ADD COLUMN match_type TEXT NOT NULL DEFAULT 'contains'
       - ALTER TABLE transactions ADD COLUMN rule_id INTEGER REFERENCES categorization_rules(id) ON DELETE SET NULL
       - CREATE INDEX idx_transactions_rule_id ON transactions(rule_id)

    2. Create rules-service.ts with:
       - computeSpecificity(conditions): pure function, returns score integer
       - matchesRule(rule, transaction): pure function, returns boolean
       - createRule(db, input): validates, computes score, INSERT, returns rule
       - updateRule(db, id, input): validates, recomputes score, UPDATE
       - deleteRule(db, id): DELETE
       - listRules(db): SELECT with JOIN to categories for category_name
       - evaluateRules(db, transaction): load all rules sorted, first match wins
       - categorizeNewTransactions(db, transactionIds): batch evaluation

    3. Modify sync-service.ts syncAccount function:
       - After the transaction insert loop, collect IDs where info.changes > 0
       - After the db.transaction() block, call categorizeNewTransactions with new IDs
       - Import categorizeNewTransactions from rules-service
  </implementation>
</feature>

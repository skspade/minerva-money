<task type="auto">
  <name>Task 1: Wire tRPC chat mutation with message state and auto-scroll</name>
  <files>packages/client/src/pages/ChatPage.tsx</files>
  <action>
Update ChatPage.tsx to add the complete message flow:

1. **Define message types** at the top of the file:
   ```typescript
   type MessageRole = 'user' | 'assistant' | 'error';
   interface ChatMessage {
     role: MessageRole;
     content: string;
   }
   ```

2. **Add state management:**
   - `messages`: `ChatMessage[]` state, initially empty
   - `sessionId`: `string | undefined` state, initially undefined
   - `messagesEndRef`: `useRef<HTMLDivElement>(null)` for auto-scroll

3. **Wire the tRPC mutation** following the SyncButton.tsx pattern:
   ```typescript
   const trpc = useTRPC();
   const chatMutation = useMutation(
     trpc.agent.chat.mutationOptions({
       onSuccess: (data) => {
         setSessionId(data.sessionId);
         setMessages(prev => [...prev, { role: 'assistant', content: data.response }]);
       },
       onError: (error) => {
         setMessages(prev => [...prev, { role: 'error', content: error.message }]);
       },
     }),
   );
   ```

4. **Implement handleSend** (replacing the stub from Plan 01):
   - Read input value from state
   - If empty/whitespace, return early
   - Add user message to messages array: `{ role: 'user', content: inputValue }`
   - Clear input
   - Call `chatMutation.mutate({ message: inputValue, sessionId })`

5. **Add auto-scroll** using useEffect:
   ```typescript
   useEffect(() => {
     messagesEndRef.current?.scrollIntoView({ behavior: 'smooth' });
   }, [messages, chatMutation.isPending]);
   ```
   Place a `<div ref={messagesEndRef} />` at the end of the message list.

6. **Render the message list** in the scrollable area (replacing the empty state):
   - If `messages.length === 0`, show the existing empty state (welcome message + example questions)
   - If `messages.length > 0`, render each message as a bubble:
     - **User messages:** right-aligned with `ml-auto bg-blue-600 text-white rounded-2xl rounded-br-sm px-4 py-2 max-w-[80%]`
     - **Assistant messages:** left-aligned with `bg-white border border-gray-200 rounded-2xl rounded-bl-sm px-4 py-2 max-w-[80%]`. Wrap content in the Markdown renderer (Task 2).
     - **Error messages:** left-aligned with `bg-red-50 border border-red-300 text-red-800 rounded-2xl rounded-bl-sm px-4 py-2 max-w-[80%]`. Prefix with a warning indicator.

7. **Typing indicator** — show when `chatMutation.isPending`:
   ```tsx
   {chatMutation.isPending && (
     <div className="flex items-center gap-1 px-4 py-2">
       <div className="flex gap-1">
         <span className="w-2 h-2 bg-gray-400 rounded-full animate-bounce [animation-delay:0ms]" />
         <span className="w-2 h-2 bg-gray-400 rounded-full animate-bounce [animation-delay:150ms]" />
         <span className="w-2 h-2 bg-gray-400 rounded-full animate-bounce [animation-delay:300ms]" />
       </div>
     </div>
   )}
   ```

8. **Disable input during flight:**
   - Set `disabled={chatMutation.isPending}` on the textarea
   - Set `disabled={chatMutation.isPending || !inputValue.trim()}` on the Send button
   - Style disabled state with `disabled:opacity-50 disabled:cursor-not-allowed`

9. **Example question clicks** should also trigger handleSend directly (not just fill the input). When user clicks an example, immediately send it as a message.

<task type="auto">
  <name>Task 2: Add markdown rendering and confirmation button parsing</name>
  <files>packages/client/src/pages/ChatPage.tsx</files>
  <action>
1. **Import react-markdown and remark-gfm** at the top of ChatPage.tsx:
   ```typescript
   import Markdown from 'react-markdown';
   import remarkGfm from 'remark-gfm';
   ```

2. **Render assistant messages with Markdown:**
   For assistant message bubbles, replace plain text rendering with:
   ```tsx
   <div className="prose prose-sm max-w-none">
     <Markdown remarkPlugins={[remarkGfm]}>{content}</Markdown>
   </div>
   ```
   - `prose prose-sm` applies typography styling from @tailwindcss/typography
   - `max-w-none` prevents prose from constraining width inside the bubble
   - This handles tables, bold, italic, lists, and code blocks automatically

3. **Parse confirmation blocks from agent responses:**

   Before rendering an assistant message, check if the response contains a confirmation JSON block. The agent may include a fenced code block like:
   ```
   ```json
   {"type":"confirmation","action":"adjust_budget","description":"Set Groceries budget to $500","params":{}}
   ```
   ```

   Create a helper function `parseConfirmation(content: string)`:
   - Use a regex to find a fenced JSON block containing `"type":"confirmation"` or `"type": "confirmation"`
   - If found, parse the JSON and extract `description`
   - Return `{ textContent: string, confirmation: { action: string, description: string } | null }`
   - `textContent` is the response with the JSON block removed
   - If no confirmation block found, return the original content with `confirmation: null`

4. **Render confirmation buttons inline:**
   When a message has a parsed confirmation:
   - Render the textContent with Markdown as normal
   - Below it, render a confirmation bar:
     ```tsx
     <div className="flex gap-2 mt-3 pt-3 border-t border-gray-200">
       <button
         onClick={() => handleSend('Yes, confirm')}
         className="px-4 py-1.5 text-sm rounded-lg bg-green-600 text-white hover:bg-green-700"
       >
         Confirm
       </button>
       <button
         onClick={() => handleSend('No, cancel')}
         className="px-4 py-1.5 text-sm rounded-lg bg-gray-200 text-gray-700 hover:bg-gray-300"
       >
         Cancel
       </button>
       <span className="text-sm text-gray-500 self-center">{confirmation.description}</span>
     </div>
     ```
   - After the user clicks Confirm or Cancel, the confirmation buttons should disappear for that message. Track which messages have been responded to using a `Set<number>` state keyed by message index.

5. **Handle the handleSend for confirmation clicks:** The existing handleSend should work — it adds a user message and calls the mutation. Confirmation clicks just send "Yes, confirm" or "No, cancel" as regular chat messages in the same session.

  <name>Task 1: Auto-fund period logic with half-split math (TDD)</name>
  <files>packages/server/src/budget/budget-service.ts, packages/server/src/budget/budget-service.test.ts</files>
  <behavior>
    - autoFundPeriod(db, period, step) where step is 1 (15th) or 2 (last day)
    - Step 1: for each category with a default, INSERT OR IGNORE a row with amount = floor(default/2), funding_step = 1
    - Step 1 skips categories that already have an allocation for this period (manual override or prior auto-fund)
    - Step 2: for each category with a default, UPDATE rows where funding_step = 1 to amount = full default, funding_step = 2
    - Step 2 does NOT touch rows where funding_step != 1 (preserves manual overrides)
    - Odd-cent default (e.g., 1501): step 1 = 750, step 2 = 1501 (750 + 751)
    - Returns count of categories funded
    - Idempotent: running step 1 twice has no additional effect (INSERT OR IGNORE)
    - Idempotent: running step 2 twice has no additional effect (no rows with funding_step=1 remain)
    - Categories with no default are not funded
  </behavior>
  <action>
    1. Add `autoFundPeriod(db: Database.Database, period: string, step: 1 | 2): number` to budget-service.ts:
       - Get all defaults via getDefaults(db)
       - If step === 1: for each default, INSERT OR IGNORE into budget_allocations with amount = Math.floor(default.amount / 2), is_default = 0, funding_step = 1. Count changes.
       - If step === 2: for each default, UPDATE budget_allocations SET amount = default.amount, funding_step = 2 WHERE category_id = ? AND period = ? AND funding_step = 1. Count changes.
       - Return total funded count
    2. Use db.transaction() to wrap all inserts/updates for atomicity.
    3. Tests: set up defaults for multiple categories, run step 1, verify half amounts. Run step 2, verify full amounts. Test idempotency by running each step twice. Test manual override preservation (set allocation before auto-fund, verify it persists). Test odd-cent rounding.
  </action>

  </verify>
